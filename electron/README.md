# Desktop shell (`electron/` and `src-tauri/`)

This directory holds the Electron desktop shell for Title IX Policy Tracker; its Rust/Tauri v2 counterpart lives in [`src-tauri/`](../src-tauri) and is **Linux-only**. The Electron shell is the shipping desktop app on **Linux and Windows 11**; both shells wrap the exact same shell-agnostic local server (`scripts/local-server.ts` / `local-bundle/local-server-entry.cjs`). See [`docs/DESKTOP-SHELLS.md`](../docs/DESKTOP-SHELLS.md) for the decision and [`docs/INSTALL.md`](../docs/INSTALL.md) for user installation.

## Architecture (standalone local mode)

1. **Single-instance lock** (`app.requestSingleInstanceLock()`) prevents concurrent writers against the embedded database directory.
2. **OS keyring integration** (`electron/keyring.ts`): reads optional ingest API keys (`CONGRESS_GOV_API_KEY`, `OPEN_STATES_API_KEY`, `LEGISCAN_API_KEY`, `LEGISCAN_SESSION_ID`) from the Freedesktop Secret Service (`org.titleixpolicytracker.desktop`) on Arch, Ubuntu, and Fedora (or macOS Keychain / `safeStorage` fallback) and passes them via environment variables when spawning the local server. On Windows there is no keyring lookup yet: users supply the same variables through their environment (documented in `docs/INSTALL.md`).
3. **Zero-TCP local IPC** (`electron/local-runtime.ts`): spawns the Next.js standalone + PGlite server bound exclusively to a Unix domain socket on Linux/macOS (`$XDG_RUNTIME_DIR/titleix-policy-tracker/app.sock`, `0700` directory, `0600` socket) or a per-user named pipe on Windows (`\\.\pipe\titleix-policy-tracker-<user>`), with persistent embedded Postgres files in `$XDG_DATA_HOME/titleix-policy-tracker/pgdata` or `%APPDATA%\titleix-policy-tracker\pgdata`.
4. **Custom scheme `app://tracker/…`**: intercepts renderer requests, injects `Cookie: authjs.session-token=<token>` on every forwarded request over `app.sock`, and strips `Set-Cookie` responses.
5. **Navigation guards on every web contents** (`electron/main.ts`, `electron/security.ts`): `app.on("web-contents-created")` attaches the same rules to the main window and to every child window opened from it (for example "Open public cell", a same-origin `target="_blank"` link). In-app URLs load in the app; other `https:` links go to the system browser; anything else is blocked; `<webview>` is refused. `windowOpenDecision()` decides `window.open` requests, and in-app child windows get the same sandboxed, context-isolated `webPreferences` and preload as the main window (`secureWebPreferences()`).

See [`docs/DESKTOP-LOCAL-AND-RUST.md`](../docs/DESKTOP-LOCAL-AND-RUST.md) for Linux packaging (AppImage, Arch, Ubuntu, Fedora) and the Milestone 3 Rust shell promotion gate.
